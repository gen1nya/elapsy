Техническое задание — iOS-приложение для счётчиков дней и виджетов

1. Общее описание

Необходимо разработать iOS-приложение для создания событий и отслеживания количества дней, прошедших с определённой даты или оставшихся до определённой даты.

Основная функция приложения — создание пользовательских событий и вывод этих событий в виде виджетов на главный экран iPhone и экран блокировки.

Приложение должно быть максимально простым и быстрым в использовании.

Пользователь должен иметь возможность:
- создать несколько событий;
- выбрать тип отсчёта;
- настроить внешний вид;
- вывести каждое событие в отдельный виджет;
- редактировать и удалять события;
- использовать приложение без обязательной регистрации.


2. Целевая платформа

Платформа:
iOS

Желательно использовать нативный стек Apple.

Рекомендуемые технологии:
- Swift;
- SwiftUI;
- WidgetKit;
- AppStorage / UserDefaults или SwiftData для локального хранения;
- StoreKit для Pro-версии и покупок;
- App Groups для обмена данными между приложением и виджетами.


3. Основные сущности

Event

Каждое событие должно содержать следующие поля:

id
Уникальный идентификатор.

name
Название события.

Пример:
Не пью
Отпуск
День рождения
Релиз игры

type
Тип отсчёта.

Возможные значения:
- elapsed;
- remaining;
- ago.

startDate
Начальная дата.
Может быть необязательной в зависимости от типа события.

endDate
Конечная дата.
Может быть необязательной в зависимости от типа события.

color
Цвет события и виджета.

widgetShape
Выбранная форма виджета.

Варианты:
- square;
- rectangular.

background
Фон виджета.
Некоторые варианты могут быть доступны только в Pro.

icon
Выбранная иконка или эмодзи.

createdAt
Дата создания события.

sortOrder
Позиция события в пользовательском порядке сортировки.


4. Типы отсчёта

Дней прошло

Используется для событий, которые начались в прошлом.

Пример:

Начальная дата:
1 января 2026

Текущая дата:
1 октября 2026

Результат:
273 дня прошло

Для данного режима обязательна:
startDate

Поле endDate не требуется.


Дней осталось

Используется для обратного отсчёта.

Пример:

Конечная дата:
1 декабря 2026

Результат:
61 день остался

Для данного режима обязательна:
endDate

Поле startDate может не отображаться.


Дней назад

Используется для событий, которые произошли в прошлом.

Пример:

Дата события:
20 сентября 2026

Результат:
11 дней назад

Для этого режима используется одна дата события.

Технически она может храниться в поле:
startDate

7. Список событий

После создания первого события пустое состояние исчезает.

Вместо него отображается вертикальный список карточек.

Каждая карточка визуально должна напоминать виджет.

Пример:

Не пью

01.01.2026 — сегодня

274

дня прошло

Карточка может состоять из двух частей.

Левая:
- иконка;
- название;
- дата или диапазон дат.

Правая:
- крупное число;
- подпись.

Между частями может использоваться вертикальный разделитель.

35. Обновление виджетов

Количество дней должно рассчитываться автоматически на основании текущей даты.

При изменении Event приложение должно вызывать обновление WidgetKit timeline.

Виджет не должен требовать ручного обновления.


36. Хранение данных

Для MVP все пользовательские события могут храниться локально.

Предпочтительно:
SwiftData.

Также возможно:
UserDefaults/AppStorage для небольшого объёма данных.

Для WidgetKit данные должны быть доступны через App Group.


37. Работа без интернета

Все основные функции должны работать полностью offline.

Интернет требуется только для:
- App Store;
- покупки Pro;
- проверки покупок;
- внешних ссылок;
- будущей синхронизации.


38. Регистрация

Для MVP регистрация не требуется.

Не должно быть:
- обязательного аккаунта;
- обязательного email;
- обязательного входа через Apple.


39. Pro-версия

Базовые функции должны оставаться бесплатными.

Free:
- создание событий;
- несколько событий;
- базовые цвета;
- базовые виджеты;
- Home Screen widget;
- Lock Screen widget.

Pro:
- дополнительные фоны;
- дополнительные темы;
- расширенная персонализация;

- отсутствие Pro-баннера.

Количество событий желательно не ограничивать даже в бесплатной версии.

42. Пустые и ошибочные состояния

Необходимо предусмотреть:
- отсутствие событий;
- ошибка сохранения;
- ошибка покупки;
- невалидный промокод;
- недоступный Pro-контент;
- удалённое событие, которое раньше использовалось в виджете.

Если событие удалено, виджет должен показывать нейтральное состояние:

Выберите событие


43. UX-требования

Интерфейс должен ощущаться нативным для iOS.

Рекомендуется использовать:
- стандартный NavigationStack;
- стандартные Picker;
- стандартные DatePicker;
- стандартные Sheet;
- стандартные ConfirmationDialog;
- SF Symbols.

Не стоит перегружать интерфейс кастомными элементами.

48. Критерии готовности MVP

MVP считается готовым, если пользователь может:

1. установить приложение;
2. открыть его;
3. создать событие;
4. выбрать тип отсчёта;
5. выбрать дату;
6. увидеть корректное количество дней;
7. изменить внешний вид;
8. сохранить событие;
9. увидеть его на главном экране приложения;
10. добавить iOS-виджет;
11. выбрать нужное событие для виджета;
12. увидеть корректное число дней без запуска приложения;
13. создать несколько независимых событий;
14. назначить разные события разным виджетам.
